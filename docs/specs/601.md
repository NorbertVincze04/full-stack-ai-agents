# Spec 601 - Initialize Frontend (Angular 18) and Backend (Node.js)

## Summary
Scaffold the empty `Frontend/` and `Backend/` folders with the minimum runnable projects described in `.github/docs/PROJECT_OVERVIEW.md`:
- `Frontend/`: Angular 18 (NgModule-based) app that starts with `ng serve`.
- `Backend/`: Node.js + TypeScript (ESM) + Express 5 project that, when started, prints `hello world` to the console.

## Scope
- Create `Frontend/` Angular 18 workspace (NgModule, routing, plain CSS, no SSR), serving on port 4200.
- Create `Backend/` project: `package.json`, `tsconfig.json`, `src/server.ts` (entry), `src/app.ts` (`createApp()` Express factory), `.gitignore`, `.env.example` (`PORT`, `CORS_ORIGIN`).
- `npm start` in each folder runs the app.
- Add `.gitignore` entries so `node_modules/`, `dist/`, `.angular/` are not committed.

## Out of scope
- PrimeNG, Font Awesome, theming, feature modules (`core/`, `features/`, `shared/`).
- Database, Cloud Foundry tunnel, auth, JWT, rate limiting, booking endpoints, admin seeding.
- Containerfiles, compose, nginx, CI/CD workflows, security agent.
- Frontend-to-backend integration (`environment.ts` / `apiUrl`, proxy).
- Real tests beyond the generated Angular default spec.

## Area
**both** - the task explicitly requires initialising both `Frontend/` and `Backend/`; the two projects are independent (no cross-calls in this task).

## Functional requirements

### Backend
- B1. Stack: Node.js, TypeScript ESM (`"type": "module"`, `module: nodenext`, `.ts` import extensions, `verbatimModuleSyntax`, `erasableSyntaxOnly`), Express 5, `cors`, `dotenv`; dev deps `typescript`, `tsx`, `@types/node`, `@types/express`, `@types/cors`.
- B2. `npm start` runs `node src/server.ts` (native TS type-stripping, see Risks/OQ1).
- B3. `npm run build` runs `tsc` -> `dist/` and must succeed.
- B4. On startup `src/server.ts` builds the app via `createApp()`, listens on `PORT` (default `3000`) and prints exactly `hello world` to stdout.
- B5. Follow backend conventions: double quotes, semicolons, trailing commas, 2-space indent; `import type` for types.
- B6. Layout leaves room for `routes/ controllers/ services/ repositories/` but creates none of them now.

### Frontend
- F1. Angular 18, generated as NgModule app (`ng new --no-standalone --routing --style=css --ssr=false`), selector prefix `app`.
- F2. `npm start` runs `ng serve`; app reachable at `http://localhost:4200`.
- F3. `npm run build` and `ng test` (default generated spec) succeed.
- F4. `.editorconfig` with UTF-8, 2 spaces, final newline, single quotes in `.ts`.
- F5. Default Angular placeholder page may be reduced to a minimal template (e.g. app title) so no boilerplate marketing content ships.

## API / data changes
None. No endpoints, no DB. The backend exposes no routes in this task.

## UI behaviour
`ng serve` compiles without errors/warnings and the browser at `http://localhost:4200` renders the root `AppComponent` without console errors. No navigation, forms, or styling requirements.

## Acceptance criteria
- [ ] AC1: `Frontend/` contains an Angular 18 workspace (NgModule-based, `@angular/core` 18.x).
- [ ] AC2: `cd Frontend && npm install && ng serve` (or `npm start`) starts successfully and serves the app on `http://localhost:4200`.
- [ ] AC3: `Backend/` contains a Node.js project with a `package.json` and a runnable entry point (`src/server.ts`).
- [ ] AC4: `cd Backend && npm install && npm start` runs and prints `hello world` to the console.
- [ ] AC5: `cd Backend && npm run build` completes without TypeScript errors.
- [ ] AC6: `node_modules/`, `dist/`, `.angular/` and `.env` are git-ignored.

AC1, AC2 (Angular runs via `ng serve`) and AC4 (backend prints "hello world") map directly to the work item's acceptance criteria; AC3, AC5, AC6 are implied hygiene.

## Risks
- **Node version conflict in the overview**: containers/CI mention Node 18, the security gate Node 20, but `node src/server.ts` (native type-stripping) needs Node >= 22.6 (enabled by default from 22.18 / 23.6), while Angular 18 supports Node 18.19+, 20.11+ and 22. Node 22 LTS satisfies all of these; Node 18 does not satisfy native TS execution.
- Angular CLI must be 18.x (`npx @angular/cli@18 new ...`); a newer global CLI would generate standalone/v19+ output.
- Corporate proxy/registry (Bosch Artifactory) may affect `npm install` on the developer machine; not a spec concern.
- Root `.gitignore` does not exist yet; add one so build output is not committed.
