# Spec 602 - Footer with copyright message

## Summary
Add a footer to the Angular app shell (`AppComponent`) that renders the copyright message `© <current year> Desk Booking. All rights reserved.` (year computed at runtime) and behaves as a sticky footer: at the viewport bottom on short pages, below the content on long pages, never hiding content. Text and behaviour were confirmed by the human.

## Scope
- Add a `<footer>` element to `Frontend/src/app/app.component.html`, outside `<router-outlet />`, so it shows on every route.
- Style the footer in `Frontend/src/app/app.component.css` (and `Frontend/src/styles.css` only if a global `html, body` rule is needed for the layout).
- Extend `Frontend/src/app/app.component.spec.ts` with a footer test.

## Out of scope
- Backend changes, API, database.
- Per-route footer visibility (the footer is shown on all routes; the header/top-bar toggling from the overview does not exist in the current scaffold).
- Footer links, navigation, social icons, i18n, theming, PrimeNG/Font Awesome.
- Extracting a dedicated `FooterComponent` / `SharedModule` (current app has only `AppComponent`; revisit when `shared/` is introduced).
- Fixing the missing `deskbookingPrj` tag on the Azure work item (ingestion concern, not an implementation concern).

## Area
**frontend** - the work item only concerns a visual element in the SPA. No data, endpoint or server behaviour is involved.

## Current state
- `app.component.html` contains `<main><h1>{{ title }}</h1><router-outlet /></main>`.
- `app.component.css` is empty; `styles.css` has only a comment.
- `AppComponent` has `readonly title = 'Desk Booking'`; the spec has 3 existing tests (create, title, h1 text).

## Functional requirements
- FR1. `AppComponent` template renders a `<footer>` after `<main>`, containing exactly `© {{ currentYear }} Desk Booking. All rights reserved.`
- FR2. The footer is rendered on every route (it lives in the root component, outside `<router-outlet />`).
- FR3. Sticky footer: the app shell is a column flex layout with `min-height: 100vh` (`100dvh` preferred with `100vh` fallback); `main` grows (`flex: 1`), so the footer is at the viewport bottom on short pages and below the content on long pages. The footer is not `position: fixed` and never overlaps content.
- FR4. The footer spans the full page width, text centred, readable contrast (WCAG AA) against its background.
- FR5. The existing title test (`h1` contains `Desk Booking`) and routing continue to work; the `<h1>` stays inside `<main>`.
- FR6. The year is derived at runtime via `new Date().getFullYear()`, exposed as `readonly currentYear` on `AppComponent`; it must not be hard-coded.
- FR7. The app shell layout needs a flex container. Since `AppComponent` has no wrapper element, apply it via `:host { display: flex; flex-direction: column; min-height: 100vh; }` in `app.component.css` (no change to `styles.css` required).

## API / data changes
None.

## UI behaviour
- Footer is visible on initial load of `http://localhost:4200` with no scrolling needed on a short page and does not overlap page content; on long pages it appears after the content at the end of the scroll.
- On narrow viewports the text wraps instead of overflowing horizontally.
- The footer is a semantic `<footer>` landmark (`contentinfo`); no interactive elements, so no keyboard/focus requirements.
- Copyright symbol is rendered as the literal character `©` (or `&copy;`), not as an image.

## Acceptance criteria
- [ ] AC1: `AppComponent`'s template contains a `<footer>` element that renders `© <current year> Desk Booking. All rights reserved.`
- [ ] AC2: The footer is displayed on every route, outside `<router-outlet />`.
- [ ] AC3: The footer is sticky: on a page with little content it is at the bottom of the viewport; on a page with long content it is below the content and does not overlap or hide it.
- [ ] AC4: The footer spans the full width and wraps correctly on narrow (mobile) viewports without horizontal scrolling.
- [ ] AC5: A unit test in `app.component.spec.ts` asserts that a `footer` element exists and its text equals `© ${new Date().getFullYear()} Desk Booking. All rights reserved.`
- [ ] AC6: Existing tests still pass; `npm run build` and `ng test` in `Frontend/` succeed without errors or warnings.
- [ ] AC7: The year is computed at runtime (no hard-coded year in template or component).

AC1 and AC3 map directly to the work item's acceptance criteria ("the footer should be at the bottom of the page always and render copyright message"); AC2, AC4, AC5, AC6, AC7 are implied hygiene.

## Risks
- A sticky footer is not always visible when content is longer than the viewport; this is the behaviour the human chose.
- A hard-coded year would become stale; mitigated by FR6/AC7. The unit test computes the year at runtime, so it does not break at year rollover.
- Applying `min-height: 100vh` on mobile browsers can cause extra scroll due to dynamic toolbars; `min-height: 100dvh` with a `100vh` fallback is acceptable.
- Work item 602 has no `deskbookingPrj` tag, so it is not picked up by the ingestion `taskFilter`; unrelated to implementation.

## Resolved Questions

2. Footer behaviour: sticky footer (viewport bottom on short pages, below content on long pages, never hides content).
